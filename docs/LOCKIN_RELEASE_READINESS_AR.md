  قبل تفرع الجلسات الفردية والجماعية. أعادت اختبارات الخادم إنتاج الخطأ قبل الإصلاح.
- إبقاء مسودة الرسالة وخطأ إرسالها عند فشل الطلب؛ تحديث الرسائل لا يمحو خطأ الإرسال.

  اكتمال الطلب السابق، وزر إعادة محاولة ظاهر عند تعذر التحميل.
- تحذير قبل مغادرة الجلسة أو فتح الشيت أو إنهاء الجلسة بملاحظة غير محفوظة؛

- 9 اختبارات Django للبوابة والجلسات والحضور والصلاحيات نجحت على SQLite
  بعد إصلاح خطأ Solo؛ SQLite لا يثبت صحة أقفال PostgreSQL.
- نجحت سيناريوهات المتصفح للجلسات والشيت والشات وإعادة المحاولة والملاحظات
  والنسخ اليدوي. شملت مراجعات سابقة اللمس والعربية وثيم النهار ومقاسات الهاتف والآيباد.
- TypeScript وESLint وRuff والاختبارات الوحدوية والبناء الإنتاجي ضمن فحوص الجولة.
- لم تتغير أي هجرة أو صلاحية أو قاعدة احتساب الوقت/النقاط أو إعداد تفعيل عام.

## بوابة النشر العام

جاهزية الكود لا تعني أن الخادم الحي حُدّث أو أن الفحوص التشغيلية اكتملت.
قبل فتح الميزة للجميع يلزم نجاح PostgreSQL CI واختبار Safari على iPhone/iPad
فعليين، والتحقق من المجدول والمهاجرتين focus 0021 و0022 على بيئة النشر.

1. نشر صور web وoperations-scheduler من الإصدار نفسه وفق عقد النشر الحالي.
2. تطبيق الهجرات المعتادة والتحقق من عمل settle_lock_in_sessions.
3. تفعيل حسابات التجربة باستخدام LOCKIN_MODE_PILOT_USER_IDS أولًا، مع
   LOCKIN_MODE_ENABLED=0. تجربة إنشاء/انضمام/خروج/استعادة جلسة بحسابين.
4. بعد الفحوص التشغيلية، تفعيل LOCKIN_MODE_ENABLED=1 ضمن إجراء النشر.
5. للإيقاف التدريجي يرجع الإعداد إلى 0؛ البوابة تسمح باستعادة الجلسات الموجودة.

لم ينفذ هذا العمل نشر VPS أو تغيير إعدادات الإنتاج، ولا يدّعي اكتمال فحص
PostgreSQL أو أجهزة Apple الفعلية. بوابة الخادم تبقى المرجع لإتاحة الميزة.
