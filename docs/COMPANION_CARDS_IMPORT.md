# بطاقات Starmo وStarsea

من إدارة المحتوى، افتح الشيت ثم «رفيق الدراسة» ثم «استيراد بطاقات المساعد (JSON)».

1. اختر نسخة الشيت وعرض الدراسة أو الملخص. الملفات ونسخها مستقلة.
2. اختر: هذا الشيت / شيتات محددة / المادة كاملة.
3. اضغط «نسخ البرومبت». يحتوي البرومبت على أسماء الشيتات ومعرّفاتها ونسخها الحالية. أرفق ملفات PDF المطابقة به.
4. ارفع JSON الناتج أو الصقه ثم اضغط «معاينة البطاقات».
5. راجع الأنواع والنصوص والصفحات. الاستيراد مسودة افتراضيًا؛ يمكنك اختيار نشر البطاقات المراجعة فورًا.
6. اضغط «تأكيد الاستيراد». إعادة رفع نفس المفاتيح تعدّل البطاقات المستوردة بدل تكرارها، وتبقي محفوظات الطلاب المرتبطة بها. لا يحذف الاستيراد البطاقات الأخرى.

يحدد AI عدد البطاقات المناسب لكل شيت، حتى 40 بطاقة، دون عدد ثابت أو حد أدنى. ويختار توزيع الأنواع حسب المحتوى: شرح خفيف، معلومات جانبية، تبسيط، طرق حفظ، ربط أفكار وتنظيم، دون حشو أو تكرار. النص عربي خفيف مع إبقاء المصطلحات الطبية بالإنجليزية عند الحاجة. المعلومات مرتبطة بالمصدر وليست نصائح علاجية.

أنواع `kind`: `understand`, `fact`, `simplify`, `memory`, `connection`, `organize`.

- `key`: مفتاح ثابت وفريد داخل الشيت، حتى 80 حرفًا إنجليزيًا/رقمًا/شرطة/شرطة سفلية.
- `page`: رقم الصفحة الفعلي في PDF بدءًا من 1؛ `null` للمعلومات العامة المستقلة عن صفحة محددة فقط، ويمكن أن تظهر بأي ترتيب أثناء القراءة. كل سؤال أو بطاقة عن فكرة محددة يجب ربطها بصفحتها، ولا يُستخدم `null` لتجنب تحديد المصدر.
- `teaser`: دعوة قصيرة للبطاقة، حتى 100 حرف.
- `question`: عنوان أو سؤال مختصر، حتى 160 حرفًا.
- `explanation`: فكرة واحدة، يفضّل 1–3 جمل قصيرة، بحد 600 حرف.
- `followup_question` و`followup_answer`: اختياريان معًا؛ 160 و280 حرفًا. لا يلزم أن تكون كل بطاقة سؤالًا.

حد الملف 2 MB، حتى 100 شيت و2000 بطاقة في الرفع الواحد، وحتى 40 بطاقة لكل شيت في الملف الواحد، وبحد إجمالي 200 بطاقة لكل شيت/نسخة/عرض بما يشمل الموجود. المنهج المقصود هو شيتات **مادة واحدة** المتاحة في الإدارة، وليس مواد مختلفة. المعاينة صالحة 15 دقيقة، وإعادة المعاينة مطلوبة إذا تغير المحتوى أو النسخة. الاستيراد دفعة واحدة: أي خطأ يمنع حفظ الدفعة كلها.

التنسيق العام (استبدل المعرفات بالمعرفات التي يولدها البرومبت):

```json
{
  "schema_version": 1,
  "subject_id": "00000000-0000-4000-8000-000000000001",
  "edition": "university",
  "view": "study",
  "sheets": [{
    "sheet_id": "00000000-0000-4000-8000-000000000002",
    "source_version_id": "00000000-0000-4000-8000-000000000003",
    "cards": [{
      "key": "concept-01-memory",
      "page": 1,
      "kind": "memory",
      "teaser": "مفتاح سريع للتذكر",
      "question": "عنوان الفكرة",
      "explanation": "وسيلة حفظ قصيرة وصحيحة تُكتب بعد مراجعة الشيت."
    }]
  }]
}
```

قبل تشغيل التحديث على الخادم: طبّق migration `content.0022_companion_card_types`. لا تتطلب الميزة أي مزود توليد آلي؛ البرومبت يساعد على إعداد الملف خارجيًا، والمشرف يراجع المحتوى قبل نشره.


## توليد بطاقات الرفيق مباشرة من Antigravity على سيرفر التطوير

أُضيف الأمر `generate_companion_cards` لتوليد أسئلة وشروح قصيرة مرتبطة بالصفحات، اعتمادًا على **ملف PDF الأصلي الجاهز** للنسخة والعرض المحددين، ثم تصدير نفس JSON الذي تقبله شاشة «استيراد بطاقات المساعد». لا يحتاج إلى مفتاح API منفصل عندما تكون أداة `agy` مثبتة ومصادقًا عليها أصلًا. يتطلب تشغيل Antigravity بواسطة مشغّل مخوّل وفي بيئة معزولة ومحدودة الصلاحيات.

مثال الشيت الواحد (استبدل المعرّف والبريد):

```bash
python manage.py generate_companion_cards \
  --sheet-id "SHEET_UUID_FROM_CONTENT_STUDIO" \
  --actor-email "AUTHORIZED_CONTENT_ADMIN@example.com" \
  --edition university --view study \
  --max-cards 40 --effort low \
  --output /tmp/starmo-sheet-draft.json \
  --report-output /tmp/starmo-sheet-review.json
```

النتيجة ملفان خاصان بالمشرف (صلاحيات 0600):

- `starmo-sheet-draft.json`: يحتوي على `schema_version` و`subject_id` و`source_version_id` وبطاقات `kind/page/teaser/question/explanation/followup` مع مفاتيح ثابتة. يُرفع في شاشة الاستيراد الحالية ويخضع لخطوتي **المعاينة ثم التأكيد**؛ الوضع الافتراضي مسودات غير منشورة.
- `starmo-sheet-review.json`: يحوي اقتباس المصدر الحقيقي لكل بطاقة ورقم الصفحة مع أرقام الصفحات التي تعذر استخراج نصها، أو التي لم تُرسل لـ Antigravity عند بلوغ حد البطاقات. لا ترفع هذا التقرير كملف استيراد.

يتحقق المولّد من أن `source_quote` مقتبس من **نفس الصفحة الفعلية** في PDF، ويتوقف عند اختلال أرقام الصفحات أو فشل الاستخراج أو فساد JSON أو تجاوز الحقول والحدود. كما يمرّر النص عبر stdin بدل وسيطات العملية، ويستخدم sandbox وبيئة متغيرات محدودة. هذا فحص مرجعي آلي، **لا يضمن صحة كل تفسير أو السؤال**؛ يلزم التدقيق العلمي قبل نشر الطلاب. لا توجد كتابة تلقائية في قاعدة البيانات أو نشر تلقائي، ولا تُرفع ملفات PDF الخاصة أو أسرار المصادقة إلى GitHub.

لشيتات متعددة أو مادة كاملة، تظل واجهة الاستيراد الحالية تدعم ملف JSON موحدًا؛ شغّل التوليد على الشيتات التي تريدها ثم اجمع `sheets` في ملف واحد فقط إذا تطابقت `subject_id/edition/view`، أو استورد كل شيت بصورة مستقلة. يُنصح باستخدام البيئة التجريبية قبل التشغيل على الخادم الحقيقي.

### إضافة المسودات مباشرة من Antigravity دون رفع يدوي

لإدخال البطاقات المُولَّدة إلى شاشة «رفيق الدراسة» كمسودات فقط، أضف `--import-drafts` إلى أمر التوليد السابق. يستخدم الأمر خدمة الاستيراد الموجودة نفسها مع معاينة موقعة والتحقق من نسخة الشيت والصفحات والمفاتيح، ويحفظ البطاقات غير منشورة (`is_published=false`). تظهر في محرر الشيت لتصحيحها ثم نشرها يدويًا. لا ينشر هذا الخيار شيئًا للطلاب ولا يغيّر ملفات PDF.

```bash
python manage.py generate_companion_cards \
  --sheet-id "SHEET_UUID_FROM_CONTENT_STUDIO" \
  --actor-email "AUTHORIZED_CONTENT_ADMIN@example.com" \
  --edition university --view study --max-cards 40 \
  --output /tmp/starmo-generated-draft.json \
  --report-output /tmp/starmo-generated-review.json \
  --import-drafts
```

إذا لم تستخدم `--import-drafts` فلن يكتب الأمر في قاعدة البيانات مطلقًا. ملفات الإخراج لا تُستبدل تلقائيًا، فأعط كل تشغيل اسمًا جديدًا. أي شيت به صفحات بدون نص أو صفحات لم تُرسل إلى Antigravity يحتاج مراجعة تقرير المصدر وإكمال محتواه قبل النشر.
