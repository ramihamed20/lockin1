# Frontend implementation capability matrix

## Evidence and contract conventions

This matrix was produced by reading the Django URL configuration, views, serializers, selectors,
permissions, models, and tests, plus the functional legacy backup in
`backups/frontend-before-legacy-replacement-20260719-0340`.  The current visual replacement in
this directory is the only visual reference.  The backup is named only as a functional reference;
none of its markup, CSS, or page layouts is a visual specification.

All paths below are relative to `/api/v1`.  Unless a row says **visitor**, the endpoint requires
the server-managed Django session.  Unsafe requests require `X-CSRFToken`; the session cookie is
HttpOnly and no access-token or refresh-token API exists.  Every non-2xx API error is shaped as
`{ error: { code, message, fields, request_id } }`.  Field errors belong beside their input and
`409` revision conflicts must offer reload/retry rather than overwriting server state.

`P25` is Django page pagination: `{count,next,previous,results}` with `page` and `page_size`
(default 25, max 100). `C` is cursor pagination: `{next,previous,results}` with `cursor` and
`page_size`; its endpoint-specific limits are stated below.  `—` means a single object or a
bounded, unpaginated response.  Request fields shown in braces are JSON unless marked multipart.

Current status uses the required classification vocabulary exactly.  "Current" describes the
replacement frontend as inspected on 2026-07-20, not an aspirational target.
